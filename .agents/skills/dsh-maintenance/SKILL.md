# DSH 环境与插件维护

面向维护 Agent。维护源代码、固定插件提交、正式安装、运行验证和清理记录，保护本地定制、未提交修改、草稿和会话。流程以本技能及其参考为唯一正文；定时任务只保存调用入口、本机绑定和触发设置。

## 入口与本机绑定

先读调用任务指定的本机 JSON 绑定。现有 Codex `dsh` 心跳默认使用 Codex 配置目录下的 `automations/dsh/maintenance-context.json`；配置目录由当前 `CODEX_HOME` 或实际用户配置确定，不猜测另一台机器的路径。绑定提供正式平台、插件源码根、临时目录、DSH Home、PR 台账、增量基线和原聊天身份，不存凭据。核对路径与实际安装；缺失或不一致时只停止依赖它的写入，继续独立只读检查。手工单项任务仅加载相关流程，不自动执行整轮更新。

Windows 保持为正式运行环境。不得因执行方便迁移到 Linux。沿用原聊天和已绑定的业务任务；活动任务正在处理相同仓库或 profile 时先核对归属，避免重复写入。互不重叠的仓库或文件范围使用多 Agent 并行；有关联的合并、安装、恢复和清理顺序执行。子 Agent 交回改动、验证、所建目录、使用者和清理条件。

## 插件修复授权

- 处理本项目任务时，官方、自维护和第三方插件发现并确认 Bug 后，可自主定位、修复和验证，无需逐次申请修复权限。在源码所属仓库修改，保留无关改动，避免只改安装产物。
- 遵循所属仓库规范，完成适用回归验证；涉及运行行为时核对实际加载版本和运行效果。
- 具有通用价值、验证通过且适合公开贡献的修复，可自主创建分支或 fork、提交推送并向对应上游提交 PR。按上游要求组织最小代码、测试和文档，排除凭据、私人配置及无关改动。PR 合并与正式发布遵循各自授权；本技能不自动授予其它项目或账号权限。

## 每轮执行

1. 读取上轮仓库提交、插件固定 pin、安装和运行摘要、验证结果、PR 台账及未清理项。批量完成独立只读检查，按实际目录发现全部维护仓库，不能只依赖旧索引数量或最近修改的插件。
2. 每轮先读取全部活跃 PR 的反馈与状态，并补查本账号历史提交，见 [上游贡献与跟进](references/upstream-prs.md)。已有稳定候选即使没有新上游提交，也要评估。
3. 对实际变化或明确证据缺口执行 [更新、同步与 Windows 交付](references/update-delivery.md)。逐仓库、逐提交和逻辑合并，保护本地改动。复用未变化且仍适用的验证证据，不为提交或推送重复测试，不对未变化环境重复安装、重启。
4. 每轮覆盖全部插件的分支、工作树和本地文件，处理本轮及历史遗留，见 [目录、分支与空间回收](references/cleanup.md)。不能只检查新建目录。
5. 保存最小可恢复基线、各插件贡献评估、PR 处理结果、清理结果和剩余事项。写入现有台账前留底、同步最新内容，按仓库和 PR 稳定身份合并，写后回读，避免并发覆盖。

## 完成与通知

分别报告源码合并、提交推送与远端 SHA、正式安装来源、实际运行验收、PR 状态及清理结果。全部适用交付、运行验收及清理完成才报告整轮完成；仍有活动会话、审批、权限或占用等阻点时，仅报告已完成范围和剩余项，继续其它独立工作。

无实际更新、可行动反馈或状态变化时保持安静，包括排队、仍在运行、等待审批等未变化状态。完成实际更新、创建或实质更新 PR、审查审批有实质进展、检查失败或修复、合并关闭、发生失败或需要用户决定时通知，附证据及对应 PR 链接。心跳调用按宿主规定返回 `NOTIFY` 或 `DONT_NOTIFY`，不因触发本身发送例行进度。仅在用户要求调整定时任务时修改现有自动化，保留未要求变更的时间、状态、原聊天和通知偏好。
