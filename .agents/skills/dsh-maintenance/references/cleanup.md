# 目录、分支与空间回收

完整每日维护与单项空间整理均读取本参考。清理是交付收尾的一部分，包括以前遗留的已完成副本。

## 放置与归属

插件源码统一放在本机绑定的 `pluginRoot` 下，正式源码使用 `packages/<plugin>`，必要临时工作树使用 `.maintenance/<repository-purpose>` 稳定子目录。优先复用现有干净工作树、缓存及已验证产物，只因真实隔离需要新建副本。不得每天在盘符根目录或其它盘新增插件副本；非插件 Core/SDK 临时目录使用固定的本机维护目录。

登记新建及保留目录的仓库、用途、使用者、恢复依赖、清理条件。仍需使用且位置不合规的目录，核对进程、依赖及链接后用 Git worktree move 或所属管理入口迁移，更新活动引用并回读；不通过再复制一份整理位置。正在被正式进程或其它任务使用的保留并记录迁移条件。正式 profile 安装产物由其生命周期管理，不随源码整理直接移动。

## 本地分支

1. 实际发现全部仓库，读取 heads、worktrees、stash、未提交和未推送内容、固定安装提交、活跃 PR 与活动任务，逐项判断保留理由。每仓库优先一个日常维护检出，贡献或验证工作树仅在必要时保留；不能因分支叫 main、master 或 codex 就机械保留或删除。
2. 已完全包含于保留分支、没有独有提交、未被工作树或活动任务/PR 使用的旧本地分支，保存小型 ref→SHA 和必要配置记录后删除。已推送但未合并的功能不能仅因有远端副本就当作多余。
3. 删除前重新核对引用未移动、提交包含关系及占用，优先正常 `git branch -d`。若仅因当前工作分支较旧而拒绝，须证明候选被另一个保留提交完整包含且无未完工作，才能使用带 expected SHA 的引用删除；不使用强制分支删除。非祖先关系但疑似已被新实现替代的单独做逻辑审查，证据不足则保留，不冒称已合并。
4. 删除后回读 refs、HEAD、暂存内容、草稿和 stash；只移除已删分支的废弃跟踪配置。每个保留分支和工作树写明用途、负责人和清理条件。远端分支不随本地整理删除，需另列精确对象、合并及 PR 证据并遵守仓库协作授权。

## 文件与副本

用户已授权本维护流程在合并、适用验证、提交推送和远端回读、正式安装与运行验收完成后，删除不再需要的临时工作树、重复源码、测试 profile、过期候选以及可重建依赖和构建产物，无需逐次请求。仅涉及测试缓存或从未使用的重复克隆时核对其不需要安装验收，不为了清理启动无关部署。

删除前简短说明精确范围和永久删除后果，核对解析后的绝对路径、重解析目标、正式安装/守护/进程/活动任务引用、Git 修改和恢复需求。不能凭日期或文件夹名批量删。不可用的旧索引不能作为“没有消费者”的证据；不把 locale 草稿、未完成迁移、业务数据和唯一验收资料误当垃圾。

已推送且远端 SHA 一致的干净副本，不为删除再做同体积备份。独有未提交内容先保存并验证最小可恢复快照；正常在用源码、活动 PR、未完成验证、唯一必要回退版本暂留，记录下一条件。新版本验收并稳定后淘汰被取代的恢复环境，只保留当前必要恢复集。

使用所属 Git/worktree 管理入口正常移除。普通 Windows 目录使用单一 PowerShell 会话和精确 LiteralPath，不跨 shell 拼接删除命令，不穿透链接删除外部目录；递归删除前验证最终绝对路径在指定范围内。硬链接文件不随意修改共享属性。不要为整洁使用 reset --hard、git clean -fdx、强推、删除 stash 或盲目清空 reflog。

自动审批拒绝的动作停止在该对象，不换工具、代理或父目录删除来绕过。记录具体限制，继续其它可执行清理；需要通知时说明自动审批拒绝了哪个动作及原因。

## 回读

核对删除路径已不存在，保留 refs、草稿和运行依赖正常；记录实际删除项、保留理由、占用、目录逻辑大小及卷可用空间变化。硬链接逻辑大小不是实际释放量；有并发写入或无法归因时明确物理释放量未知。子 Agent 交回清单后由主 Agent 汇总，仍受占用或审批限制的项目纳入下轮增量基线，不能把本轮结束写成全部清空。
