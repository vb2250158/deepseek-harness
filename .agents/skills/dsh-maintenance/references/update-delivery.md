# 更新、同步与 Windows 交付

执行拉取、合并、同步、安装或恢复时读取本参考。源码、私有环境配置和正式安装分别核验，不用版本号相同代替提交及加载来源一致。

## 保护与合并

1. 核对每个仓库的真实 origin/upstream、当前分支和 HEAD、工作树、暂存区、stash、未提交和未推送内容，以及正在写入的任务。保存可完整恢复受影响内容的快照；不把未提交草稿顺手纳入维护提交。
2. 拉取上游后逐提交阅读差异、依赖和变更说明，区分本地定制与上游实现。逐个逻辑选择合入、适配或保留；不要用整树覆盖、机械接受一侧或重置来替代审查。环境同步同样逐文件和逻辑合并，保留机器专属配置、会话索引及私有数据。
3. 在源码所属仓库修改。只针对变化运行相关行为测试、文档检查、构建和必要启动验证，复用未变证据；失败先修复再验证，不弱化断言求通过。遵守各仓库发布规范，公共插件仓库的必要元数据也要写后回读。
4. 检查公开差异并脱敏，按主题提交、普通推送，回读远端目标分支 SHA。固定插件 pin 必须引用远端可取得的提交，版本与该提交包元数据一致；先确认远端可取，再更新清单和同步安装。私有环境只同步到已确认的私有目标，不发布本机凭据、内部地址、账号或会话数据。

## 安装与恢复的唯一执行者

同一正式 profile 的安装、恢复和重启只由一个明确的任务执行。写前检查安装事务、现有守护、正式进程、目录占用和其它活动任务；已有事务由原任务完成，本轮继续独立检查。事务结束后重新读取实际版本、配置和进程，用最新基线合并，不启动第二套恢复，不用旧快照覆盖它的结果。

## 候选验收与切换

1. 旧服务保持运行。候选在独立端口、进程和数据目录中，通过受支持的 `dsh` profile 入口完整启动，验证真实接口、资源、依赖与退出。测试不复用正式凭据、锁、写入目录，不连接正式业务路由、消息端或后台任务。源码测试、构建成功和安装指针更新均不能替代启动验收。
2. 切换前备齐不可变候选、状态快照和已验证回退版本。核对正式会话空闲；活动业务仍在运行时继续其它独立工作，不为维护强行打断。
3. 需要冷更新时，通过正式生命周期入口暂停本轮确认的守护，安全停止所属空闲实例，确认占用释放后安装。不得终止归属不明的进程，不在停服后现场调试。
4. 写后回读实际安装路径、固定提交及加载来源，恢复原守护，核验新 Host、代理、必要子进程、真实接口与会话保留。清除本轮已完成的暂停状态，避免遗留停服标记。
5. 切换或事务恢复失败，先恢复到明确一致且可用的已验证版本；后续修复回到隔离环境，恢复完成前不继续依赖写入。恢复无法完成时报告具体影响和缺口，继续不依赖该实例的工作。

保留本轮源码与安装映射、必要测试结果、远端 SHA、运行验收和恢复状态，交给清理流程判定旧候选是否仍需保留。未变环境不重复安装或重启。
