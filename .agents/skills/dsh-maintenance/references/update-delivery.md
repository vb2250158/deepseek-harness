# 更新、同步与 Windows 交付

执行拉取、合并、同步、安装或恢复时读取本参考。源码、私有环境配置和正式安装分别核验，不用版本号相同代替提交及加载来源一致。

交付范围服从技能正文和本机绑定。源码 Web 运行使用官方源码启动入口，仅准备本次变化需要的 Host、Client、Web 产物及插件依赖；运行于 Windows 不要求制作 Windows 安装包。未使用的桌面、移动、SDK 与可执行包不纳入例行维护，已通过且输入未变化的检查直接复用。

测试以仓库声明的当前宿主与环境版本为唯一支持目标；不下载旧宿主或执行多版本、跨平台兼容矩阵。核对必要行为回归、已有实际数据保留和该固定组合的源码 Web 运行即可。公开版本说明同时区分受测候选与正式安装，不能把源码验证写成已实装。

## 保护与合并

1. 核对每个仓库的真实 origin/upstream、当前分支和 HEAD、工作树、暂存区、stash、未提交和未推送内容，以及正在写入的任务。保存可完整恢复受影响内容的快照；不把未提交草稿顺手纳入维护提交。
2. 拉取上游后逐提交阅读差异、依赖和变更说明，区分本地定制与上游实现。逐个逻辑选择合入、适配或保留；不要用整树覆盖、机械接受一侧或重置来替代审查。环境同步同样逐文件和逻辑合并，保留机器专属配置、会话索引及私有数据。

   配置三方合并先按对象或具有稳定身份的数组项处理整项删除，再合并保留项的字段，不得逐叶拼回缺少身份字段的残片。只有真实目标 Schema 证明本机差异仅为默认扩充时，才沿用上游整项删除；本机存在实质改动时报告整项冲突，保留原值与现场。

3. 在源码所属仓库的现有主分支修改，不新建插件分支。交接中的其它分支先逐提交和逻辑合入主分支；独有草稿继续保护。只针对变化运行相关行为测试、文档检查、构建和必要启动验证，复用未变证据；验证发现的问题在所属源码修复并重跑受影响检查，再接续组合验收和实装，不停在失败报告或单包测试成功。遵守各仓库发布规范，公共插件仓库的必要元数据也要写后回读。
4. 检查公开差异并脱敏，按主题提交、普通推送，回读远端目标分支 SHA。固定插件 pin 必须引用远端可取得的提交，版本与该提交包元数据一致；先确认远端可取，再更新清单和同步安装。私有环境只同步到已确认的私有目标，不发布本机凭据、内部地址、账号或会话数据。

## 安装与恢复的唯一执行者

同一正式 profile 的安装、恢复和重启只由一个明确的任务执行。写前检查安装事务、现有守护、正式进程、目录占用和其它活动任务；已有事务由原任务完成，本轮继续独立检查。事务结束后重新读取实际版本、配置和进程，用最新基线合并，不启动第二套恢复，不用旧快照覆盖它的结果。

进程身份结合实际 Home、profile、监听端口和服务回读的进程号确认；正式实例和隔离候选可能共用同一源码根，不能只凭源码路径认定归属。

界面自动化曾暂停时，核对后续人类指示。用户明确恢复或继续需要界面验收的交付时，按当前授权恢复必要操作并记录旧暂停已续接；没有恢复指示时保持暂停。新的暂停、缺权限、法律协议或活动业务会话按其实际范围处理，不能为维护强行继续。

## 候选验收与切换

先核对固定 Git 包的运行入口。需要 `prepare` 或构建时，只对已审定来源启用必要脚本，用声明工具链验证正常 Git 安装可生成 Host、Client 产物，再启动候选。构建或打包缺陷在所属源码修复；有来源和字节证明的手工产物补齐仅用于隔离诊断，不能代替跨机安装交付。

安装元数据按正式 profile 的位置核对：逐项确认锁文件中 `link:` 解析到已审定源码，不直接复用隔离目录的相对链接。用最终位置等价的隔离 profile 执行同一官方受管命令及冻结参数，保持已锁版本、提交和完整性不变。离线缓存按全部锁定版本及所需发布时间核验；缺失或过期时补齐公开 registry 元数据，再重跑原检查，不关闭供应链策略。

1. 旧服务保持运行。候选使用现有主分支的固定提交或无分支源码导出，保留当前正式插件和已登记的本机集成，仅加入本轮预期变化；在独立端口、进程和数据目录中，通过受支持的 `dsh` profile 入口完整启动，验证组合的真实接口、资源、依赖、受影响页面与退出。版本、API 字段和页面入口从对应 owner 的定义及当前页面读取，实际 served 资源按本次导航重新发现，不沿用旧 URL 或猜测 revision。测试不复用正式凭据、锁、写入目录，不连接正式业务路由、消息端或后台任务。源码测试、构建成功和依赖导入均不能替代组合启动及适用页面验收。

   候选与开发、测试源码各自安装独立 `node_modules`，不得用可写 junction 或 link 借用候选依赖树；包管理器的自动安装会改写 workspace link。受管测试使用声明的明确 Node 和工具入口，并核对实际依赖解析目录。

2. 切换前备齐不可变候选、状态快照和已验证回退版本。停服前用目标插件的真实 Schema 或受支持入口校验现有持久化配置及受影响组合，不能只验合成配置；私有内容在本机核对，凭据和聊天数据不得复制到预览。核对正式会话空闲；活动业务仍在运行时继续其它独立工作，不为维护强行打断。
3. 需要冷更新时，通过正式生命周期入口暂停本轮确认的守护，安全停止所属空闲实例，确认占用释放后安装。不得终止归属不明的进程，不在停服后现场调试。

   改名或替换依赖树前，完成所有需要原依赖解析的读取、校验及凭据解密。安装失败的恢复集覆盖原依赖、配置和安装器写入的 journal、baseline、重启标记；失败文件先留底，不把仅恢复包清单视为恢复完成。
4. 安装后的版本、实际来源、同步器 schema 与 baseline 由独立新进程回读，避免安装前后相同模块 URL 的 Node ESM 及依赖图缓存。核对实际安装路径、固定提交及 served 字节，恢复原守护，核验新 Host、代理、必要子进程、真实接口与会话、Bot 绑定和配置保留。共享清单与实际插件数量的差异逐项对应已登记的本机集成，不硬编码数量或用总数相等代替逐项核对。读取失败沿原事务先回滚并恢复，再回隔离环境诊断。清除本轮已完成的暂停状态，避免遗留停服标记。
5. 切换或事务恢复失败，先恢复到明确一致且可用的已验证版本；后续修复回到隔离环境，恢复完成前不继续依赖写入。恢复无法完成时报告具体影响和缺口，继续不依赖该实例的工作。

Windows 跨卷归档暂停标记时，先复制并回读哈希，再移除本轮持有的原标记。后台守护使用已验证的隐藏启动入口，回读实际存活进程、绑定的 Host 与健康状态；启动命令返回 PID 不代表守护已恢复。

保留本轮源码与安装映射、必要测试结果、远端 SHA、运行验收和恢复状态，交给清理流程判定旧候选是否仍需保留。未变环境不重复安装或重启。

## 共享配置与收尾

安装前保护凭据、账号与绑定。运行中的正常 OAuth token、刷新时间和过期时间更新由凭据 owner 负责；核对安装是否造成丢失时区分这些正常更新，不为追求旧字节相等回写过期 token。

正式验收后，按实际固定提交和运行配置定向合并共享清单与环境快照，保留机器专属字段、凭据、会话及无关草稿。仅向已确认的授权目标提交所需改动、普通推送并回读远端分支与实际内容；共享发布未完成时保留已验证正式状态和具体待办，不重复安装。完成后按[清理流程](cleanup.md)处理已交付副本和旧分支，并在原台账闭合对应步骤。
