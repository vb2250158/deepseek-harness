# Agent Note: 在步骤准备前解析部署路由

Status: implemented

[English](2026-10-24-step-model-resolution.md) | 中文

## Problem

部署策略可以重定向用户选择的模型，同时保留原始选择。在提示词组装后才确定目标，会使条件工具、提示词变量与实际请求使用不同的路由。持久选择临时目标又会导致删除规则后无法恢复原始来源。

## Decision

Agent 循环在每个拟议步骤的工具解析与提示词组装之前，等待一次 `agent/resolve-model`。默认值是捕获的原始选择。循环复制并冻结返回的有效选择，并在重试中保留它。现有请求 hook 不能再改变该固定路由或推理强度。

路由监听器负责校验目标，必要时用既有 `model/selection` 事件记录尚未持久化的原始后备选择，不选择临时目标。异步校验后，监听器保留用户后来作出的选择，而不记录已过时的原始来源。请求 header 继续记录实际分派的路由；不增加持久事件或重放状态。

[适配器容量决策](2026-07-20-routed-model-context-and-compaction-policy.zh.md)继续有效：已准备适配器仍持有有效路由的容量与可选压缩策略。本决策增加更早的路由操作，不替代其职责。

## Alternatives considered

**在 `agent/request` 中重定向。** 工具与组装已经捕获路由，此时改变路由会破坏三者的一致性。

**持久选择目标。** 后续步骤会丢失原始选择，删除规则后无法恢复它。

**每次重试重新解析。** 规则变化可能改变路由，而复用的提示词与工具集仍为另一个模型准备。

## Consequences

每个步骤增加一次需等待的 waterfall。没有监听器时，选择及持久输出不变。解析失败或取消会阻止该次提议的工具解析、提示词组装、用户输入接纳与模型分派。规则变化从下一个步骤生效，路由策略的日志说明由中间件负责。
